1. EXECUTIVE SUMMARY & CORE PARADIGM
================================================================================
CyberShield is a real-time, browser-telemetry-driven User and Entity Behavior 
Analytics (UEBA) security platform engineered around the Gartner Continuous Adaptive 
Risk and Trust Assessment (CARTA) framework:

- Never Trust, Always Verify: Authentication is not a single gate at login, 
  but a continuous dynamic calculus evaluated throughout the user lifecycle.

2. CRITICAL FEASIBILITY AUDIT & EDGE-CASE MITIGATIONS
================================================================================
A Karpathy-level engineer does not just describe how a system works; they proactively 
identify where it could fail and explain the exact mitigation:

A. SQLite Concurrency & Database Locks:
   - Risk: Under high-concurrency attack storms, SQLite file-locking can throw 
     OperationalError: database is locked.
   - Mitigation: CyberShield utilizes short-lived connection lifecycles (connect, execute, 
     commit, close per function) with row_factory = sqlite3.Row and lightweight WAL-mode 
     compatibility. For multi-node enterprise deployments, the database layer cleanly 
     abstracts to PostgreSQL.

B. Client Time Drift vs Server Clock:
   - Risk: User's local browser clock can be altered or set incorrectly, causing false 
     temporal anomalies.
   - Mitigation: The engine correlates client HH:MM with server UTC/local timestamps 
     and enforces a generous 3-hour variance window, flagging only late-night 
     off-hours (22:00 - 06:00) deviations.

C. IP Geolocation Spoofing & VPN Ingress:
   - Risk: Reverse proxies or VPNs mask true client origins.
   - Mitigation: CyberShield inspects X-Forwarded-For headers, strips commas to avoid 
     header injection, compares coordinates using the Haversine formula, and cross-references 
     IP prefixes against a Threat Intelligence database of known Tor exit nodes and proxies.

D. SMTP Email Rate Limits & Failover:
   - Risk: Gmail SMTP limits daily relay quotas or authentication fails without app passwords.
   - Mitigation: Zero-downtime dual-dispatch. If live SMTP fails or is unconfigured, the 
     engine automatically logs passcodes to the terminal and renders on-screen for 
     instant local validation.

6. DEEP-DIVE ALGORITHMS & MATHEMATICAL MODELS
================================================================================

A. HAVERSINE VELOCITY ENGINE (behaviour_engine.py)
   - Earth radius R = 6371.0 km
   - Computes angular distance:
     a = sin²(Δlat/2) + cos(lat1) * cos(lat2) * sin²(Δlon/2)
     c = 2 * atan2(sqrt(a), sqrt(1-a))
     distance = R * c
   - Velocity = distance / max(hours_diff, 0.1)
   - If distance > 350 km and velocity > 800 km/h:
     Flag: Impossible Travel (+35 Risk Points).

B. DECEPTION HONEYTOKEN LOGIC (app.py)
   - Endpoint: /download/file/<filename>
   - Legitimate files -> normal download + T1078 logging.
   - Decoy file ("Confidential_Executive_Salaries_2026.xlsx"):
     * Trust score forced to 0.
     * is_locked set to 1 (automated quarantine).
     * Logged under MITRE T1204 (User Execution / Honeytoken Trap).
     * In-app notification dispatched; session terminated.

C. SLIDING-WINDOW ATTACK CORRELATION (attack_detector.py)
   - Window size: N = 10 recent activities.
   - Brute Force: >= 3 failed logins [MITRE T1110]
   - Account Takeover: Failed attempts -> Success from new device/location [MITRE T1078]
   - Data Exfiltration: Off-hours login -> Large file access [MITRE T1048]
   - Impossible Travel: Distant coordinates within impossible timeframe [MITRE T1078.003]
   - Anonymous Ingress: Tor exit node or high-risk proxy match [MITRE T1090]
